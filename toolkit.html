Lab 1 · Crime hotspot analysis

Predict where and when crime is more likely, not who will commit it.

SCENARIOYou are the analyst for a district control room. House burglaries have risen in the last two months. Where should next week’s night patrols focus?
Colab
Google Sheets
QGIS or Kepler.gl
Orange (optional)

Steps

  1. Get open dataDownload street-level crime CSVs from data.police.uk, the Chicago Data Portal or data.gov.in, or generate a synthetic file with latitude, longitude, date, time and offence type.
  2. Clean itIn Sheets or pandas: remove rows with no coordinates, standardise dates, keep one offence type (for example burglary).
  3. Map itLoad the points into Kepler.gl (runs in the browser) or QGIS and switch on a heatmap. Compare day and night.
  4. Find time patternsMake an hour × weekday table. Which time blocks carry most incidents?
  5. Build a simple forecastCount incidents per grid cell per week, then compare a baseline (average of the last 4 weeks) with a model. Run the starter code below in Colab.
  6. Audit the resultAre hotspots only where police already patrol or where people report more? Note this in your briefing.
import pandas as pd
from sklearn.ensemble import GradientBoostingRegressor
df = pd.read_csv("crimes.csv", parse_dates=["date"])
df["cell"] = df.lat.round(2).astype(str) + "_" + df.lon.round(2).astype(str)
w = df.groupby(["cell", pd.Grouper(key="date", freq="W")]).size().rename("n").reset_index()
w["last4"] = w.groupby("cell").n.transform(lambda s: s.shift(1).rolling(4).mean())
w = w.dropna()
m = GradientBoostingRegressor().fit(w[["last4"]], w.n)
w["pred"] = m.predict(w[["last4"]])
print(w.nlargest(10, "pred")[["cell", "pred"]])   # top-10 cells to review
Starter only. Improve it by adding hour, weekday, holidays and nearby-cell counts, and test on weeks the model has not seen.

Lab 2 · Suspect and case-link analysis

Find patterns and links between cases. Do not score individual people.

SCENARIOSeven mobile-snatching cases in three weeks, on two bikes, in three areas. Do they share an offender or modus operandi (MO)? What should investigators check next?
Colab
Gephi
Neo4j Aura Free
NotebookLM

Steps

  1. Prepare a synthetic case tableColumns: case id, date, place, MO text, vehicle, description of offender, items taken. Ask a chat assistant to generate 20 fictional rows.
  2. Match MO by meaningConvert each MO description to an embedding and rank the cases most similar to a target case (code below).
  3. Draw a link chartNodes: cases, vehicles, phone numbers, places. Edges: shared attributes. Use networkx in Colab, or import a CSV into Gephi.
  4. Build the timelinePut the cases on a map and a timeline. Check travel time between scenes.
  5. Write a leads listFor each link, state the evidence, how strong it is, and what would disprove it.
from sentence_transformers import SentenceTransformer, util
m = SentenceTransformer("all-MiniLM-L6-v2")
e = m.encode(cases.mo_text.tolist())
sim = util.cos_sim(e, e)
print(sim[0].argsort(descending=True)[:4])   # cases most like case 0

import networkx as nx
G = nx.Graph()
G.add_edges_from([("Case 1", "Bike-A"), ("Case 4", "Bike-A"), ("Case 4", "Area-C")])

Lab 3 · Analyse case files with NotebookLM

NotebookLM answers from the sources you add and shows citations, which makes checking easier.

SCENARIOYou receive five documents on an online-fraud ring: two public advisories, a synthetic FIR, a synthetic bank-statement summary and news clippings. Brief your superintendent in ten lines.
  1. Create a notebookOpen NotebookLM with a Google account and start a new notebook named for the exercise.
  2. Add sourcesUpload PDFs or Google Docs, paste text or add web links. Use only public or synthetic material.
  3. Ask grounded questionsUse the prompts below. Open each citation and confirm it says what the answer claims.
  4. Generate study aidsTry the briefing document, timeline, FAQ, mind map and audio overview if they are available in your account.
  5. Verify and exportMark any claim you cannot trace to a source as [TO VERIFY], then copy the result into a Google Doc.

Prompts to copy

Build a dated timeline of events. Give the source for every entry.
List every person, phone number, account and place mentioned, and which documents mention each.
Where do these documents contradict each other?
What information is missing that an investigator should collect next?
Summarise for a Superintendent of Police in 10 lines. Mark anything uncertain.

Private mode · AI without sending data out

Everything runs on your own computer or a closed network. No uploads, no accounts, no cloud.

SCENARIOYou must analyse a real set of complaints and call records. Policy says nothing may reach any outside service. Can you still use AI? Yes: run the models locally.

Three levels of privacy

Level 1

Local and offline

Install tools while online, then switch the network off. Data never leaves the laptop.

Level 2

Air-gapped machine

A computer that is never connected. Bring tools and models in on a scanned USB drive and check file hashes.

Level 3

Department server

An on-premise server with access control and logs, so a team can share one private model.

Local replacements for cloud tools

NotebookLM → AnythingLLM or Open WebUI

Ask questions over your own files with a local model. Runs on your machine.

ChatGPT, Gemini, Claude → Ollama, LM Studio, GPT4All

Open models such as Llama, Mistral, Gemma and Qwen run without internet.

Colab → Jupyter or VS Code

Same Python code on your own PC. Install packages from a saved folder for offline use.

Cloud speech-to-text → Whisper locally

whisper.cpp or faster-whisper transcribe call recordings on your own computer.

Online maps → QGIS offline

Keep a local base map. Browser map tools usually fetch map tiles from the internet.

Protect the files

Full-disk encryption (BitLocker or LUKS) or a VeraCrypt container, with cloud sync turned off.

Build a private AI assistant

  1. Install while onlineInstall Ollama from its official site, then download a small model and a local embedding model (commands below).
  2. Go offlineTurn off Wi-Fi and unplug Ethernet. Run the model again to prove it still works.
  3. Mask personal details firstReplace names, phone numbers and addresses with codes. Keep the code key in a separate encrypted file.
  4. Ask your questions locallyUse the Python script below, or a desktop app such as AnythingLLM pointed at Ollama. Switch off telemetry in every tool’s settings.
  5. Check nothing leavesWhile it runs, list network connections and confirm there are none to outside addresses.
  6. Clean upDelete temporary files and chat history, and empty the recycle bin.
ollama pull llama3.2
ollama pull nomic-embed-text

import requests, pathlib
note = pathlib.Path("note.txt").read_text()
r = requests.post("http://localhost:11434/api/generate", json={
    "model": "llama3.2", "stream": False,
    "prompt": "Summarise in 10 lines. Mark uncertain items [TO VERIFY].\n\n" + note})
print(r.json()["response"])      # talks only to your own computer
import re
t = open("note.txt").read()
t = re.sub(r"\b\d{10}\b", "[PHONE]", t)
t = re.sub(r"\b[A-Z][a-z]+ [A-Z][a-z]+\b", "[NAME]", t)   # crude: check by hand
open("note_masked.txt", "w").write(t)

Secure handling checklist

Be honest about the limits

  • Small local models are weaker and can make things up. Verify even more carefully.
  • Small models need roughly 8 GB of RAM; larger ones need more. A GPU helps but is not required.
  • Check each model’s licence before official use.
  • Running locally protects the data, but you still need legal authority and approval to analyse it.

Ethics and safety

Predictive tools can repeat old bias. Use them to support decisions, never to replace them.

Do

  • Use public or synthetic data for training
  • Predict places and times, not individuals
  • Keep a human responsible for every decision
  • Verify each AI claim against the source
  • Record how AI was used, and test for bias
  • Follow department policy and the law

Don’t

  • Paste FIRs, victim or witness details into public AI tools
  • Treat AI output as evidence or proof
  • Rate named people as likely offenders
  • Run face recognition on real people in practice
  • Send officers to a place only because a model said so
  • Hide AI use from supervisors or courts

Known problems to discuss

  • Feedback loops: more patrols find more crime there, so the data points there again.
  • Biased data: records show what was reported and recorded, not all crime.
  • Opacity: if you cannot explain a result, you cannot defend it.
  • Privacy: in India, consider the Digital Personal Data Protection Act 2023 and the rules on electronic evidence. Elsewhere, apply your local law.

Before any real deployment

  • Legal basis and written approval
  • Data location, vendor terms and access control
  • Testing on past data and a bias review
  • Audit trail, supervisor sign-off and a way for the public to complain
